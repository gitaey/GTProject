# 설명 방식

코드를 새로 쓰거나 고쳤을 때는 **무엇을 왜 했는지** 초등학생도 이해할 만큼 쉬운 한국어로 설명한다.

- 순서: 왜 필요한지 → 무슨 문제를 막는지 → 어떻게 동작하는지.
- 전문 용어(트랜잭션, 비동기, 프록시 등)를 쓰면 바로 옆에 쉬운 말로 한 번 더 풀어준다.
  예: "비동기(=일을 시켜놓고 기다리지 않고 다른 일부터 하는 것)"
- 버그를 고쳤을 때: 원래 뭐가 문제였는지 → 왜 생겼는지 → 어떻게 고쳤는지.
- 쉬운 설명은 코드 블록 **밖** 일반 텍스트로 쓴다. 코드 안 주석은 기존 컨벤션대로 짧게 유지한다.
