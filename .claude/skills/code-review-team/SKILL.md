# code-review-team

arch-reviewer, security-reviewer, perf-reviewer, style-reviewer를 **동시에** 실행하고(팬아웃),
메인 세션(너)이 네 결과를 하나의 리포트로 합친다(팬인).

**실행 방식:** 서브에이전트. 네 `Agent` 호출을 **한 메시지에** 넣고 각각 `run_in_background: true`,
`model: "opus"`, `subagent_type`에 에이전트 이름. 리뷰어끼리는 서로 기다리지 않는다.

## Phase 0 — 범위 정하기

- 사용자가 경로/브랜치/커밋을 지정하면 그대로.
- 지정 없으면: 커밋 안 된 변경(`git status`, `git diff`) + `master` 대비 커밋(`git diff master...HEAD`).
  둘 다 없으면 최근 커밋 몇 개를 범위로 할지 사용자에게 묻는다.
- "전체 감사"면 프로젝트 전체. 이때는 영역(frontend 지도 모듈 / frontend 나머지 / backend / bot)을 나눠
  각 리뷰어에게 우선순위를 준다.
- 범위(파일 목록과 이유)를 `_workspace/review/00_scope.md`에 쓴다. 이전 리뷰 파일이 있으면
  `_workspace/review_prev_<YYYYMMDD>/`로 옮긴다. 부분 재실행("보안만 다시")이면 해당 리뷰어만 다시 돌리고 나머지 파일은 재사용한다.

## Phase 1 — 팬아웃

각 리뷰어 프롬프트에: `00_scope.md` 경로, 자기 산출물 경로(`_workspace/review/{arch,security,perf,style}.md`),
"코드는 고치지 말 것", 이 리뷰의 목적(예: 지도 모듈 재개편 직후라 이식성을 중점적으로).
기다리는 동안 결과를 예측하지 않는다.

## Phase 2 — 팬인 (통합 리포트)

네 파일을 모두 읽고 `.claude/review-reports/<YYYY-MM-DD>-<scope-slug>.md`를 쓴다.

```
# 코드 리뷰 — <범위> (<날짜>)
## 요약            전체 건수, 심각도별 분포, 한 문단 총평
## 지도 이식성       (위반이 있으면 맨 위. 없으면 "위반 없음 — audit-portability 통과"와 확인 방법)
## 치명 / 높음 / 보통 / 낮음
   - [관점] 제목 — 파일:라인 — 문제 — 실제로 곤란해지는 상황 — 고치는 방향
## 리뷰어 간 이견
## 살펴본 범위 / 못 본 범위 (리뷰어별)
```

- **중복 합치기:** 같은 파일·같은 원인을 여러 리뷰어가 지적하면 한 항목으로 합치고 관점을 모두 표시한다.
- **지우지 않기:** 리뷰어끼리 판단이 다르면 하나를 고르지 말고 "이견"에 둘 다 쓴다.
- **검증:** 치명·높음 항목은 해당 파일:라인을 직접 열어 사실인지 확인한 뒤 싣는다. 확인이 안 되면 "미확인"으로 표시.
- 비밀값은 값을 옮기지 않고 위치만 쓴다.

`.claude/review-reports/`는 gitignore 대상이다. 이 저장소는 public이라, 고치기 전의 취약점 목록이 공개되면 안 된다.

## Phase 3 — 보고

사용자에게: 리포트 경로, 치명·높음 목록(짧게), 바로 고칠 것을 추천 순서로. **자동으로 고치지 않는다** —
사용자가 고치라고 하면 규모에 따라 직접 고치거나 fullstack-pipeline(구현 에이전트 + qa)으로 넘긴다.
마지막에 "리뷰 기준이나 리포트 형식에서 바꾸고 싶은 점이 있나요?"라고 묻는다.

## 에러 처리

| 상황 | 대응 |
|---|---|
| 리뷰어가 결과 파일 없이 종료 | 1회 재호출. 또 실패하면 리포트에 "<관점> 리뷰 누락"을 명시하고 나머지로 완성 |
| 범위가 너무 커서 리뷰어가 일부만 봄 | 그대로 받고 "못 본 범위"에 기록. 필요하면 그 범위로 부분 재실행 제안 |
| 리뷰어가 코드를 수정함 | `git diff`로 확인해 되돌리지 말고 사용자에게 알린다 (리뷰어는 수정 금지 규칙) |
| `Agent type '<이름>' not found` | 같은 세션에서 새로 만든 에이전트라 아직 등록 전이다. `subagent_type: "general-purpose"`로 호출하고 프롬프트 첫 줄에 "`.claude/agents/<이름>.md`를 읽고 그 역할·원칙·산출물 규칙을 그대로 따른다"를 넣는다 |

## 테스트 시나리오

- **정상:** "이번 지도 리팩토링 종합 리뷰해줘" → 범위 = 커밋 안 된 변경 → 4명 동시 실행 → 네 파일 수집 →
  치명·높음 직접 확인 → 리포트 작성 → 요약 보고.
- **에러:** perf-reviewer가 결과 없이 종료 → 1회 재호출 → 또 실패 → 리포트 요약에 "성능 관점 누락, 부분 재실행 권장" 명시.
