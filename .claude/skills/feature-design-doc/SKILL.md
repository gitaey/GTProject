# 기능 설계문서 우선 작성

새로운 기능을 개발하거나, 기존 기능에 새로운 동작을 추가/구현하라는 요청을 받으면,
**코드를 한 줄이라도 작성하기 전에** 이 스킬을 따라 설계문서를 먼저 만든다.

## 적용 대상 / 제외 대상

- 적용: 새 기능 개발, 새 도메인 추가, 기존 기능에 새로운 요구사항 추가, 화면/API 신규 추가 등
  "무엇을 만들지 설계가 필요한" 작업
- 제외: 단순 버그 수정, 오타/문구 수정, 이미 확정된 설계를 그대로 따르는 단순 리팩토링,
  설정값 변경, 의존성 업데이트 등 설계 여지가 거의 없는 작업
- 애매하면 사용자에게 "이번 건 설계문서 없이 바로 진행해도 될까요?"라고 짧게 확인하고 넘어간다.

## 진행 순서

### 1. 요구사항 파악
구현에 들어가기 전에 필요한 정보(범위, 관련 도메인, 기존 코드와의 관계 등)를 먼저 파악한다.
필요하면 코드베이스를 탐색(Grep/Glob/Read, 또는 Explore 에이전트)하되, 아직 코드는 수정하지 않는다.
요구사항이 불명확해서 설계 방향이 갈리는 경우에만 AskUserQuestion으로 확인한다.

### 2. 설계문서 작성
`.claude/design-docs/` 디렉토리에 아래 파일명 규칙으로 **직접 파일을 생성**한다
(사용자 글로벌 지침의 "파일을 직접 생성하지 말 것"은 이 스킬처럼 설계문서 작성이 목적인
작업에는 적용하지 않는다 — 설계문서 자체가 산출물이기 때문).

- 파일명: `YYYY-MM-DD-<기능-슬러그>.md` (슬러그는 영문 kebab-case)
  예: `.claude/design-docs/2026-09-15-mymap-share-link.md`
- 디렉토리가 없으면 새로 만든다.

설계문서는 다음 항목을 포함한다 (내용이 없는 항목은 "해당 없음"으로 명시, 생략하지 않음):

```markdown
# <기능명> 설계문서

- 작성일: YYYY-MM-DD
- 관련 도메인: (frontend/backend 어느 쪽, backend라면 domain 이름)

## 1. 배경 및 목적
왜 이 기능이 필요한지, 어떤 문제를 해결하는지

## 2. 요구사항
- 기능 요구사항 (사용자가 뭘 할 수 있어야 하는지, bullet)
- 비기능 요구사항 (성능/권한/제약 등, 해당 시)

## 3. 설계 상세
- 데이터 모델 / 엔티티 (backend인 경우)
- API 설계 (endpoint, request/response, 해당 시)
- 프론트엔드 구조 (컴포넌트, 상태관리(zustand store), 페이지 라우트, 해당 시)
- 기존 코드와의 연결점 (CLAUDE.md 컨벤션 준수 여부 — 예: 새 도메인은 다른 도메인을 참조하지
  않는 독립 모듈로 설계)

## 4. 영향 범위
- 신규 생성 파일 목록
- 수정 예정 파일 목록

## 5. 작업 순서 (체크리스트)
- [ ] 단계 1
- [ ] 단계 2
- ...

## 6. 고려사항 / 트레이드오프
대안으로 고려했지만 채택하지 않은 방식과 이유 (있는 경우)
```

### 3. 사용자 승인 대기
설계문서 작성을 마치면, 문서 경로와 핵심 요약(요구사항/설계 방향/작업 순서)을
채팅에 간단히 보여주고 **구현을 시작하기 전에 사용자 승인을 받는다.**
"이대로 진행할까요?" 형태로 명확히 묻는다.

- 사용자가 승인하면 → 설계문서의 작업 순서 체크리스트를 따라 구현을 진행하고,
  단계가 끝날 때마다 체크리스트 항목에 체크(`- [x]`)한다.
- 사용자가 수정을 요청하면 → 설계문서를 먼저 갱신한 뒤 다시 승인을 받는다.
- 구현이 끝나면, 설계문서 상단에 "## 구현 완료" 메모나 날짜를 추가해 최신 상태를 반영한다
  (문서를 지우지 않고 이력으로 남긴다).

## 주의사항

- 이 스킬은 CLAUDE.md의 코딩 컨벤션(네이밍, 도메인 독립성, 커밋 메시지 규칙 등)과
  `.claude/rules/explain-simply.md`(쉬운 설명 규칙)를 대체하지 않는다. 설계문서 작성 이후
  실제 구현 단계에서는 기존 프로젝트 규칙을 그대로 따른다.
- 설계문서 작성 자체를 이유로 git commit/push를 자동으로 하지 않는다
  (커밋/푸시는 사용자가 명시적으로 요청할 때만).
