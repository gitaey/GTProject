# 지도 모듈 테이블 DDL (PostgreSQL)

- 기준: 2026-09-30 작업트리 (BK-1: `LayerUserAccess`의 User FK 제거, BK-2: `GisErrorCode`/`GisUserContext` 분리 반영)
- 대상: 백엔드 지도 도메인 `map`, `mymap`, `geotiff`, `wind` (`geoserver`는 테이블 없음 — GeoServer REST 호출만)
- **DB 실측: 안 함.** 로컬 DB가 운영 DB라 조회도 하지 않았다. 아래 DDL은 전부 `@Entity`/`@Table`/`@Column`에서 도출했다.
  실제 DB와 맞춰 보려면 8절의 읽기 전용 SQL을 사람이 직접 돌린다.
- 표기: **코드 확인** = 파일:라인에서 읽은 사실 / **추론** = Hibernate·Spring Boot 기본 동작에서 유추 / **확인 필요** = 실측해야 확정
- 경로의 `…/`는 `backend/src/main/java/com/gtp/`를 줄인 것이다.

## 1. 이 DDL과 `ddl-auto: update`가 만든 실제 스키마가 다를 수 있는 곳

| # | 항목 | 내용 | 근거 |
|---|---|---|---|
| 1 | 네이밍 | `application.yml`에 naming 설정이 없어 Spring Boot 기본 `CamelCaseToUnderscoresNamingStrategy`가 적용된다. `@Column(name)`이 없는 필드는 `camelCase` → `snake_case`. `geo_tiff_files`가 여기에 해당(`originalName` → `original_name`) | 코드 확인: `backend/src/main/resources/application.yml` jpa 절(naming 없음) / 추론: Boot 기본 전략 |
| 2 | 길이 없는 String | `@Column(length)`가 없으면 Hibernate 기본 `varchar(255)`. `geo_tiff_files`의 문자열 컬럼 전부 | 추론 |
| 3 | 타입 매핑 | `Long` id + IDENTITY → `bigint generated by default as identity`, `double`/`Double` → `float(53)`(= `double precision`), `LocalDateTime` → `timestamp(6)`, `LocalDate` → `date`, `boolean` → `boolean`, `int`/`Integer` → `integer` | 추론: Hibernate 6.6 PostgreSQLDialect |
| 4 | DB DEFAULT 없음 | `@Builder.Default`(예: `status = "PROCESSING"`, `opacity = 1.0`)는 **자바 쪽 기본값**이다. Hibernate DDL에는 `DEFAULT`가 안 붙는다. MyBatis로 옮기면 INSERT에서 값을 직접 넣거나 아래 DDL의 "권장 DEFAULT"를 켠다 | 코드 확인: 각 엔티티 `@Builder.Default` |
| 5 | UNIQUE 이름 | `@UniqueConstraint`에 이름이 없어 Hibernate가 `UK` + 해시로 자동 명명한다. 아래 `uk_*` 이름은 이 문서가 붙인 것 | 코드 확인: 엔티티 `uniqueConstraints` / 확인 필요: 실제 이름 |
| 6 | FK | 이 문서의 DDL은 **FK를 만들지 않는다**(BK-1 방침: 도메인 독립·이식 단순화). 단 GTProject 현재 DB에는 `@ManyToOne` 때문에 Hibernate가 만든 FK가 **남아 있을 것**이다: `tbl_layer.group_id`, `tbl_layer_group.parent_id`, `tbl_layer_permission_access.layer_id`, `tbl_layer_user_access.layer_id`, `tbl_user_map_feature.user_map_id`, `tbl_user_map_permission_access.user_map_id`, `tbl_user_map_user_access.user_map_id`. BK-1 이관 SQL을 실행하기 전이면 `tbl_layer_user_access.user_id → tbl_user`도 남아 있다 | 추론 / 확인 필요: 8절 SQL |
| 7 | 인덱스 | 엔티티에 `@Index`가 하나도 없다. PostgreSQL은 FK 컬럼에 인덱스를 자동으로 만들지 않으므로 현재 DB에는 **PK와 UNIQUE 외 인덱스가 없을 것**이다(누가 수동으로 만들지 않았다면). 특히 `tbl_user_map_feature.user_map_id` | 코드 확인: 엔티티 전체 `@Index` 0건 / 확인 필요: `pg_indexes` |
| 8 | 잔재 컬럼 | `ddl-auto: update`는 컬럼을 추가만 하고 지우거나 타입을 바꾸지 않는다. 옛 엔티티에 있던 컬럼이 남아 있을 수 있다(예: `tbl_wind_frame`은 GFS→LDAPS 교체 이력이 있음) | 확인 필요 |
| 9 | 시각 값을 채우는 주체 | `tbl_layer`, `tbl_layer_group`: Spring Data Auditing(`@CreatedDate`/`@LastModifiedDate`, `GtpApplication`의 `@EnableJpaAuditing`). `tbl_user_map`: Hibernate `@CreationTimestamp`/`@UpdateTimestamp`. `geo_tiff_files.uploaded_at`: `@CreationTimestamp`. `tbl_wind_frame.created_at`: 생성자에서 `LocalDateTime.now()`. **MyBatis에선 전부 SQL에서 `now()`로 직접 넣어야 한다** | 코드 확인: `…/domain/map/entity/Layer.java:79-85`, `LayerGroup.java:35-41`, `…/domain/mymap/entity/UserMap.java:65-71`, `…/domain/geotiff/entity/GeoTiffFile.java:30-31`, `…/domain/wind/entity/WindFrameEntity.java:52` |
| 10 | 시간대 | `timestamp`(시간대 없음)에 JVM 기본 시간대 값이 들어간다. 예외: `tbl_wind_frame.valid_time`은 코드가 UTC로 계산해 넣고, `cycle_date`/`cycle_hour`는 **KST** 기준이다(엔티티 주석 `// 0, 6, 12, 18 (UTC)`는 옛 GFS 시절 설명이라 현재 코드와 다름) | 코드 확인: `WindFrameEntity.java:30`, `…/domain/wind/service/WindDataService.java:42, 83, 106-117` |

지오메트리는 hibernate-spatial/PostGIS 타입을 쓰지 않고 **GeoJSON 문자열(TEXT)** 로 저장한다(코드 확인: `UserMapFeature.java:6-10` 주석).
좌표계는 **EPSG:4326**이다(업로드 때 서버가 4326으로 변환해서 저장). 이 테이블들에는 PostGIS 확장이 필요 없다.

## 3. 레이어 (`domain/map`)

```sql
-- 레이어 그룹. parent_id로 중첩(루트는 NULL)
CREATE TABLE tbl_layer_group (
    id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        varchar(100) NOT NULL,
    parent_id   bigint,                         -- 논리 참조: tbl_layer_group.id (FK 없음)
    sort_order  integer      NOT NULL,          -- 권장 DEFAULT 0 (자바 기본값 0)
    created_at  timestamp(6),                   -- 앱이 now() 입력 (Auditing)
    updated_at  timestamp(6)                    -- 앱이 now() 입력 (Auditing)
);

-- 레이어 정의
CREATE TABLE tbl_layer (
    id           bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name         varchar(100) NOT NULL,
    type         varchar(20)  NOT NULL,         -- WMS, WMTS, TMS, WFS, MVT, GEOJSON, ARCGIS, XYZ (서버가 대문자화)
    source_type  varchar(20)  NOT NULL,         -- OPENAPI, GEOSERVER, GEOWEBCACHE, XYZ, STATIC (서버가 대문자화)
    url          varchar(500) NOT NULL,         -- 키 자리표시자 허용(프론트 호스트가 치환)
    layer_name   varchar(200),
    style_name   varchar(100),
    style_config text,                          -- JSON 문자열
    format       varchar(50),
    projection   varchar(20),
    min_zoom     integer,
    max_zoom     integer,
    opacity      float(53)    NOT NULL,         -- 권장 DEFAULT 1.0
    visible      boolean      NOT NULL,         -- 권장 DEFAULT true
    sort_order   integer      NOT NULL,         -- 권장 DEFAULT 0
    group_id     bigint,                        -- 논리 참조: tbl_layer_group.id (NULL = 미분류)
    group_name   varchar(100),                  -- 비정규화: 저장 시점의 그룹 이름
    description  varchar(300),
    created_at   timestamp(6),
    updated_at   timestamp(6)
);

-- 권한 키별 허용 레이어
CREATE TABLE tbl_layer_permission_access (
    id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    permission  varchar(20) NOT NULL,           -- 권한 키(역할 코드 또는 세부 권한 코드, 7절 참고)
    layer_id    bigint      NOT NULL,           -- 논리 참조: tbl_layer.id
    CONSTRAINT uk_layer_perm_access UNIQUE (permission, layer_id)
);

-- 사용자별 개인 레이어 선택 (행이 0개 = 개인 설정 없음)
CREATE TABLE tbl_layer_user_access (
    id        bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id   varchar(50) NOT NULL,             -- 호스트 사용자 id 문자열 (BK-1 후 FK 없음)
    layer_id  bigint      NOT NULL,             -- 논리 참조: tbl_layer.id
    CONSTRAINT uk_layer_user_access UNIQUE (user_id, layer_id)
);
```

근거(코드 확인): `Layer.java:12-85`, `LayerGroup.java:12-41`, `LayerPermissionAccess.java:7-24`, `LayerUserAccess.java:11-28`.

주의점:
- `tbl_layer.group_name`은 비정규화 사본이다. `LayerGroupService.update`로 그룹 이름을 바꿔도 **기존 레이어의 `group_name`은 안 바뀐다**.
  레이어를 저장하거나 재정렬할 때만 갱신된다(코드 확인: `Layer.java:106, 113`, `…/domain/map/service/LayerGroupService.java:39-45`).
- `permission` 길이가 20이다. 역할/세부권한 코드가 20자를 넘으면 저장이 실패한다.
- FK가 없으므로 삭제 순서는 앱이 지킨다: 레이어 삭제 시 `tbl_layer_permission_access` → `tbl_layer_user_access` → `tbl_layer`
  (코드 확인: `…/domain/map/service/LayerService.java:156-162`).
- **그룹 삭제는 자식 그룹·소속 레이어를 정리하지 않는다**(코드 확인: `LayerGroupService.java:48-51`). FK가 남아 있는 현재 DB에선
  참조가 있으면 삭제가 500으로 실패하고(추론), FK가 없으면 고아가 남는다. 트리 조립이 "부모 없는 그룹은 루트로, 그룹 없는 레이어는
  미분류로" 처리하므로 화면은 깨지지 않는다(코드 확인: `LayerService.java:51-67`).

```sql
CREATE TABLE geo_tiff_files (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

    stored_name    varchar(255) NOT NULL,       -- UUID + 확장자 (titiler가 file:///data/{stored_name} 로 읽음)

    uploaded_at    timestamp(6),                -- 앱이 now() 입력
    uploaded_by    varchar(255),                -- 업로드한 사용자 id (현재는 클라이언트가 보낸 폼 값)
    file_size      bigint,
    min_lon        float(53),                   -- EPSG:4326 범위. 처리 전/실패 시 NULL
    min_lat        float(53),
    max_lon        float(53),
    max_lat        float(53),
    status         varchar(255) NOT NULL,       -- PROCESSING, READY, FAILED (권장 DEFAULT 'PROCESSING')
    error_message  varchar(255)                 -- 255자 초과 메시지 주의(4절과 같은 문제)
);

-- 바람장 프레임. 완전한 최신 사이클 1개만 유지(새 사이클이 완전해진 뒤 더 오래된 사이클 삭제)
CREATE TABLE tbl_wind_frame (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    cycle_date     date         NOT NULL,       -- LDAPS 사이클 날짜 (KST)
    cycle_hour     integer      NOT NULL,       -- 3, 9, 15, 21 (KST)
    forecast_hour  integer      NOT NULL,       -- leadHour 0 ~ (wind.forecast-hours - 1)
    valid_time     timestamp(6) NOT NULL,       -- 유효시각 (UTC 값)
    data_json      text         NOT NULL,       -- grib2json 형식 [{header, data}, {header, data}] (U, V)
    created_at     timestamp(6) NOT NULL        -- 앱이 now() 입력
);
-- 같은 프레임이 두 번 저장되는 것을 DB가 막는다(서버 둘이 동시에 갱신해도 안전). ddl-auto는 이 인덱스를 만들지 않으므로 직접 만든다
CREATE UNIQUE INDEX ux_wind_frame_key ON tbl_wind_frame (cycle_date, cycle_hour, forecast_hour);

-- 스칼라 변수(기온 temp·습도 humi·강수량 rain): (사이클, 예보시간, 변수)당 1행. 선택 기능(wind.fields가 비면 비어 있음)
CREATE TABLE tbl_wind_scalar (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    cycle_date     date         NOT NULL,       -- 바람 프레임과 같은 사이클 키 (KST)
    cycle_hour     integer      NOT NULL,
    forecast_hour  integer      NOT NULL,
    var_code       varchar(16)  NOT NULL,       -- temp, humi, rain
    valid_time     timestamp(6) NOT NULL,       -- UTC 값
    data_json      text         NOT NULL,       -- {header:{…,scale,unit}, data:[정수|null,…]} 값 = data[i] × scale
    created_at     timestamp(6) NOT NULL
);
CREATE UNIQUE INDEX ux_wind_scalar_key ON tbl_wind_scalar (cycle_date, cycle_hour, forecast_hour, var_code);
```

근거(코드 확인): `GeoTiffFile.java:9-46`, `WindFrameEntity.java:16-53`, `WindDataService.java:42, 106-125`.

주의점:
- `geo_tiff_files`는 `tbl_` 접두사 규칙의 예외다(`.claude/rules/backend.md`).
- **유니크 인덱스 순서.** 옛 서버 코드는 같은 프레임을 중복 저장했다. 기존 DB에 `ux_wind_frame_key`를 만들려면 먼저 중복이 없어야 한다: `SELECT cycle_date, cycle_hour, forecast_hour, COUNT(*) FROM tbl_wind_frame GROUP BY 1,2,3 HAVING COUNT(*) > 1;`가 0행인지 확인하고, 있으면 id가 큰 쪽만 남기고 지운 뒤 만든다. 새 서버 코드는 이미 있는 프레임을 건너뛰고 첫 정리에서 중복도 지우므로, **새 코드를 배포한 뒤 한 번 갱신된 다음** 인덱스를 만드는 것이 안전하다(먼저 만들면 옛 코드의 재저장이 유니크 위반으로 실패한다).
- `tbl_wind_frame.data_json`은 행당 수 MB다. `SELECT *`로 여러 행을 읽으면 메모리가 크게 든다. `query-spec.md` 바람 절에
  컬럼과 행 수를 줄인 SQL을 적었다.

## 7. 초기 데이터(seed)

- **코드에 지도 테이블 seed는 없다.** `global/init/DataInitializer`는 역할·권한·관리자만 넣는다. 지도 도메인 밖에서 지도 엔티티·리포지토리를
  참조하는 곳은 0건이고 `src/main/resources`에 `.sql` 파일도 없다(코드 확인: grep).
- 빈 테이블이어도 지도는 뜬다(레이어 트리 `{groups: [], ungroupedLayers: []}`). 배경지도는 프론트 설정이지 이 테이블이 아니다(추론: FE 코어 배경지도 모드).
- 레이어 패널에 뭔가 보이게 하려면 관리 화면(GTProject는 앱 쪽 `/map-admin/layer`) 또는 SQL로 넣는다. 예시(값은 전부 자리표시자):

```sql
INSERT INTO tbl_layer_group (name, parent_id, sort_order, created_at, updated_at)
VALUES ('<그룹 이름>', NULL, 0, now(), now());

INSERT INTO tbl_layer (name, type, source_type, url, layer_name, style_name, format, projection,
                       opacity, visible, sort_order, group_id, group_name, created_at, updated_at)
VALUES ('<레이어 이름>', 'WMS', 'GEOSERVER', '<WMS 서비스 URL>', '<작업공간:레이어>', NULL, 'image/png', 'EPSG:3857',
        1.0, true, 0, <그룹 id>, '<그룹 이름>', now(), now());

-- 권한 트리를 쓸 때만: 권한 키별 허용 레이어
INSERT INTO tbl_layer_permission_access (permission, layer_id) VALUES ('<권한 키>', <레이어 id>);
```

- `url`에 API 키를 넣지 않는다. VWorld처럼 키가 필요한 URL은 키 자리표시자를 쓰고 프론트 호스트가 키를 주입한다
  (코드 확인: `frontend/packages/gis-map/src/core/types/layer.ts:11` 주석). 키 값은 DB 덤프·문서·커밋에 남기지 않는다.
- **권한 키 주의:** 관리 화면은 역할에 세부 권한이 있으면 **세부 권한 코드**, 없으면 **역할 코드**로 저장한다(코드 확인:
  `frontend/src/app/map-admin/layer/page.tsx:69-73`). 지도 화면 어댑터는 기본으로 **역할 코드**를 키로 조회한다(코드 확인:
  `frontend/packages/gis-map/src/adapters/rest/layerTree.ts:15`). 세부 권한이 있는 역할이면 트리가 비어 보일 수 있다 → `query-spec.md` 불일치 표 참고.

## 9. Oracle / Tibero로 옮길 때

| PostgreSQL | Oracle 12c+ | Tibero | 메모 |
|---|---|---|---|
| `bigint GENERATED BY DEFAULT AS IDENTITY` | `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY` 또는 시퀀스 | 시퀀스 권장(확인 필요: 버전별 IDENTITY 지원) | MyBatis INSERT는 `<selectKey order="BEFORE">SELECT 시퀀스.NEXTVAL FROM DUAL</selectKey>`가 두 DB 모두 무난 |
| `varchar(n)` | `VARCHAR2(n CHAR)` | `VARCHAR2(n CHAR)` 또는 `VARCHAR(n)` | 기본이 BYTE 길이면 한글 1자 = 3바이트(AL32UTF8)라 `varchar(100)`이 한글 33자로 줄어든다 → **`CHAR` 단위 필수** |
| `text` | `CLOB` | `CLOB` | `geometry_json`, `properties_json`, `data_json`, `style_config` 등. MyBatis는 `jdbcType=CLOB` |
| `boolean` | `NUMBER(1)`(0/1) 또는 `CHAR(1)`('Y'/'N') | 같음 | Oracle 23ai부터 BOOLEAN 지원. VO는 boolean 유지하고 TypeHandler로 변환 |
| `float(53)` | `BINARY_DOUBLE` 또는 `NUMBER` | 같음 | |
| `timestamp(6)` | `TIMESTAMP(6)` | `TIMESTAMP(6)` | `now()` → `SYSTIMESTAMP` 또는 `CURRENT_TIMESTAMP` |
| `date` | `DATE`(시각 포함) | `DATE` | `cycle_date` 비교 시 0시로 맞춰 넣기 |
| 빈 문자열 | `''` = `NULL` | 같음(확인 필요) | `properties_json`이 `''`면 NULL → 스트리밍 코드가 `{}`로 대체하므로 영향 없음. `name`이 `''`면 NOT NULL 위반 |
| 식별자 길이 | 12.2 미만은 30바이트 | 확인 필요 | `tbl_user_map_permission_access`가 **정확히 30자**다. 이 문서의 제약·인덱스 이름은 모두 30자 이내 |
| 예약어 | `type`, `format`, `status`, `url`, `name`, `permission`, `projection`, `visible`은 Oracle 예약어(reserved=Y) 목록에 없다(추론: 일반 지식) | 확인 필요 | 대상 DB에서 `SELECT keyword FROM V$RESERVED_WORDS WHERE reserved = 'Y'`로 최종 확인 |
| `LIMIT n` | 12c+ `FETCH FIRST n ROWS ONLY`, 11g는 `ROWNUM` | 확인 필요 | 바람 최신 프레임 조회에서 사용 |
